一、公开入口与实际处理顺序
----------------------------------------------------------------
公开入口（沿用 README 参数）：

  python -m newsletter_preview \
      --contacts contacts.csv \
      --template template.txt \
      --segment newsletter \
      --out previews

四个参数均为必需：--contacts（联系人 CSV）、--template（模板
文本）、--segment（筛选值）、--out（输出目录）。参数定义见
_build_parser（__init__.py:116-126，required=True 见 122-125）。
入口链：__main__.py:7-8 以 sys.exit(main()) 调用 main()
（__init__.py:129-162）。

main() 中读取、校验、筛选、替换、报告写入的实际顺序
（__init__.py:131-158，全部包在同一个 try 内）：

  1. 读取联系人 CSV 文本（__init__.py:133，_read_text
     定义于 26-36）；
  2. 读取模板文本（__init__.py:134，同一函数）；
  3. 解析并完整校验全部 CSV 行（__init__.py:135，
     _parse_contacts 定义于 39-76）；
  4. 校验模板占位符（__init__.py:136，_validate_template
     定义于 79-86）；
  5. 准备输出目录：不存在则创建，存在则要求为空且可写
     （__init__.py:137，_prepare_out_dir 定义于 89-102）；
  6. 按 segment 筛选（__init__.py:140）；
  7. 按 CSV 顺序逐人替换并写预览文件（__init__.py:142-147，
     写盘函数 _write_file 定义于 105-113），同时累积报告清单；
  8. 组装报告并写 report.json（__init__.py:149-158）。

成功返回 0（__init__.py:162）。任何一步抛出本模块的 InputError
（__init__.py:22-23）都由 __init__.py:159-161 捕获，向标准错误
输出一行“错误：……”，返回 2；标准输出不产生内容。
argparse 层面的参数错误（缺参数等）由 argparse 在进入 try 之前
自行处理，同样以退出码 2 终止（__init__.py:130），其标准错误为
argparse 用法信息，不带“错误：”前缀。

关键次序结论：第 1-4 步（两份输入的读取与全部校验）全部先于
第 5 步（创建/检查输出目录）。因此输入校验失败时，输出目录尚未
被创建或写入（详见第四节与第六节）。

----------------------------------------------------------------
二、读取与校验（第 1-4 步）
----------------------------------------------------------------
2.1 UTF-8 输入

  两份输入均以 open(path, "r", encoding="utf-8", newline="")
  读取（__init__.py:29）。文件不存在、无法以 UTF-8 解码或其他
  读取错误一律转为 InputError（__init__.py:31-36），退出 2，
  且发生在输出目录准备之前。写出同样使用 UTF-8 且 newline=""
  （__init__.py:108），不做换行转换。

2.2 必需字段与表头

  CSV 首行必须是表头（空文件报错，__init__.py:43-47），且必须
  包含 name、email、segment 三列（REQUIRED_COLUMNS 定义于
  __init__.py:16；逐列检查于 49-56）。列顺序不限，额外列允许
  存在但被忽略——记录只按列名取这三列（__init__.py:66）。
  缺任一必需列即 InputError，错误信息给出实际表头（53-55）。
  每一数据行的字段数必须与表头一致，否则报错（__init__.py:61-65）。

2.3 未匹配行同样参与校验

  _parse_contacts 先遍历并校验 CSV 的全部数据行、返回完整记录
  列表（__init__.py:58-73），筛选在其后的第 6 步才发生
  （__init__.py:140）。因此某行即使 segment 不等于筛选值、最终
  不会生成预览，其 name、email、segment 字段为空或仅含空白时
  仍会导致整体失败（逐字段检查见 67-72，行号取 reader.line_num）。
  注意 .strip() 仅用于“是否为空”的判定（68 行），存入记录与
  后续比较、替换使用的都是未修剪的原值。
  CSV 词法错误由 csv.Error 捕获并转为 InputError（74-75）。

2.4 模板占位符

  完整双花括号占位符由 PLACEHOLDER_RE = r"\{\{([^{}]*)\}\}"
  识别（__init__.py:19）；只允许 {{name}}（KNOWN_PLACEHOLDER
  定义于 17）。出现任何其他完整占位符（如 {{age}}）即 InputError，
  信息中点名该变量（__init__.py:81-86）。未闭合或不成对的花括号
  不匹配该正则，按普通文字保留。

----------------------------------------------------------------
三、筛选与替换（第 6-7 步）：谁会看到哪份正文
----------------------------------------------------------------
3.1 筛选语义

  筛选就是一次 Python 字符串相等比较：
  c["segment"] == args.segment（__init__.py:140）。
  因此：
  - 区分大小写："Newsletter" 不等于 "newsletter"，该联系人不
    入选；
  - 不修剪空白：CSV 中的值与命令行筛选值都按原文比较，
    "newsletter "（带尾空格）不匹配 "newsletter"；
  - 不做包含、前缀或任何归一化匹配。

3.2 编号、顺序与共享邮箱

  入选记录保持 CSV 中的出现顺序（__init__.py:140 列表推导），
  自 1 起连续编号（enumerate(..., start=1)，__init__.py:142），
  文件名格式 preview-{编号:04d}.txt（__init__.py:143），即
  preview-0001.txt、preview-0002.txt……编号连续、不因未匹配行
  留空号。
  多条记录共享同一邮箱不做任何合并：每条入选记录各生成一份独立
  预览、在报告清单中各占一项（循环逐条写入与追加见
  __init__.py:142-147）。

3.3 替换与正文保留

  正文由 template_text.replace("{{name}}", contact["name"])
  一次性生成（__init__.py:145）：
  - 替换值（姓名）不再被解析：即使姓名里含有花括号文字，也不会
    被当作占位符二次处理；
  - 模板中除 {{name}} 以外的全部文字原样保留；
  - 读写均以 newline="" 打开（29、108 行），换行与正文逐字节
    保留，模板末尾的换行同样保留。

  由此可直接核对“谁会看到哪份正文”：第 N 个入选联系人的姓名被
  写入 preview-000N.txt，邮箱与文件名的对应关系由报告清单给出
  （3.4 与第五节表格）。

3.4 报告内容（第 8 步）

  报告为一个 JSON 对象（__init__.py:149-154），字段依次为：
  - "template"：模板原文（template_text，含原始换行，150 行）；
  - "segment"：命令行给出的筛选值原文（151 行）；
  - "matched_count"：入选联系人数，len(matched)（152 行）；
  - "previews"：清单，每项 {"email": ..., "file": ...}，
    按生成顺序排列（147 行追加，153 行入报告）。
  序列化用 json.dumps(..., ensure_ascii=False, indent=2) 并在
  末尾补一个换行（__init__.py:155-158），中文不转义。
  matched_count、previews 清单长度、实际写出的 preview 文件数
  三者一一对应。零匹配时退出 0：不生成任何 preview 文件，只生成
  report.json，其中 matched_count 为 0、previews 为空清单 []
  （循环 142-147 一次不执行，报告仍在 155-158 写出）。

四、输出目录与两类失败的区别
----------------------------------------------------------------
4.1 输出目录规则（_prepare_out_dir，__init__.py:89-102）

  - 目录不存在：创建它（os.makedirs，99-102 行）；
  - 路径已存在但不是目录：拒绝，InputError（92-93 行）；
  - 目录已存在且非空：拒绝，InputError（94-95 行），退出 2，
    目录中原有内容不变（程序在此中止，不会写任何文件）；
  - 目录已存在、为空但不可写：拒绝，InputError（96-97 行）；
  - 创建目录失败：InputError（99-102 行）。
  写文件一律用 open(path, "x") 独占新建（__init__.py:108），
  文件已存在也转为 InputError（110-111 行），不覆盖任何已有文件。

4.2 输入校验失败：不产生任何输出

  读取失败、CSV 缺列/字段为空/字段数不一致/解析失败、模板含未知
  变量，均发生在第 1-4 步，先于输出目录准备（__init__.py:133-136
  对 137 行）。因此：
  - 若 --out 目录尚不存在，运行后仍不存在（不会被创建）；
  - 若 --out 目录已存在且为空，运行后仍是空目录（不会留下文件）。
  非空目录拒绝（4.1）同样不改变其原有内容。

4.3 写入失败：退出 2，但无回滚保证

  第 7-8 步逐个写文件（__init__.py:142-147 写预览，155-158 写
  report.json）。若中途某个 _write_file 因操作系统层错误抛出
  InputError（__init__.py:112-113），控制流同样跳到 159-161，
  退出码仍为 2；但源码中没有任何删除或回滚逻辑——此前已经写出的
  预览文件会保留在输出目录中（例如报告写入失败时，此前写出的
  preview 文件已全部存在）。因此“退出 2 且无输出”的结论只适用于
  第 4.2 节的输入校验阶段；写入阶段失败后，目录可能处于部分写入
  状态，本文不承诺、源码也不提供原子性或回滚。

五、固定样例：甲、乙、丙（预期结果，非实测记录）
----------------------------------------------------------------
以下为完整固定样例。联系人为合成数据，邮箱使用 RFC 2606 保留的
example.invalid 虚构域名；甲、乙同属 newsletter 且共享同一邮箱，
丙属 archive。预期结果逐字依据第一至四节引用的源码推导，可照此
自行执行核对，但它不是某次运行的记录。

5.1 输入文件

contacts.csv（UTF-8，首行表头，恰好三行数据）：

  name,email,segment
  甲,shared@example.invalid,newsletter
  乙,shared@example.invalid,newsletter
  丙,bing@example.invalid,archive

即：甲（第 2 行）与乙（第 3 行）segment 均为 newsletter、邮箱
均为 shared@example.invalid；丙（第 4 行）segment 为 archive，
邮箱 bing@example.invalid。

template.txt（UTF-8，内容为“你好，{{name}}！”后接恰好一个
换行；共 13 个字符、21 字节）：

  你好，{{name}}！
  （文件末尾一个换行）

5.2 命令（与 README 相同的参数形式）

  python -m newsletter_preview \
      --contacts contacts.csv \
      --template template.txt \
      --segment newsletter \
      --out previews

5.3 预期结果

  - 退出码 0，标准错误为空（__init__.py:162；成功路径不打印）；
  - previews/ 目录在不存在时被创建，其中恰好三个文件：
    preview-0001.txt、preview-0002.txt、report.json，无其他文件；
  - preview-0001.txt 的完整内容为五个字符加一个换行（共 6 个
    字符、16 字节）：
      你好，甲！\n
  - preview-0002.txt 的完整内容同样为五个字符加一个换行：
      你好，乙！\n
    两份正文均保留模板末尾的换行（__init__.py:145 配合 108 行
    newline="" 写入）；
  - 不为丙生成任何预览（"archive" != "newsletter"，
    __init__.py:140）。

  谁会看到哪份正文（编号、邮箱与正文的对应关系）：

    CSV 行 | 姓名 | 邮箱                    | segment    | 入选 | 文件              | 正文（含末尾换行）
    ------+----+-------------------------+------------+----+-------------------+------------------
     2    | 甲 | shared@example.invalid  | newsletter | 是 | preview-0001.txt | 你好，甲！\n
     3    | 乙 | shared@example.invalid  | newsletter | 是 | preview-0002.txt | 你好，乙！\n
     4    | 丙 | bing@example.invalid    | archive    | 否 | （不生成）        | （不生成）

  共享邮箱 shared@example.invalid 收到的是两条互相独立的记录，
  对应两份不同正文，不合并、不去重（__init__.py:142-147）。

  report.json 的完整预期内容（中文不转义、两空格缩进、文件末尾有
  一个换行；__init__.py:155-158）：

  {
    "template": "你好，{{name}}！\n",
    "segment": "newsletter",
    "matched_count": 2,
    "previews": [
      {
        "email": "shared@example.invalid",
        "file": "preview-0001.txt"
      },
      {
        "email": "shared@example.invalid",
        "file": "preview-0002.txt"
      }
    ]
  }

  "template" 保留模板原文（含 {{name}} 占位符与末尾换行），
  "segment" 保留筛选值原文；matched_count 为 2，与清单两项、
  两份预览文件严格对应；清单顺序即 CSV 顺序，邮箱与文件名一一
  关联（__init__.py:147、149-154）。

六、三类输入失败样例（预期结果，非实测记录）
----------------------------------------------------------------
下列三种输入均在第 3-4 步校验失败（先于输出目录准备），预期退出
码 2；标准错误为一行“错误：……”且不含未捕获异常的 Traceback
（__init__.py:159-161）；尚不存在的输出目录不会被创建，已存在的
空目录保持为空（4.2 节）。除注明处外，其余输入沿用第五节。

6.1 模板含未知变量 {{age}}

  将 template.txt 改为在末尾换行前再加一行 {{age}}，例如内容为
  “你好，{{name}}！\n{{age}}\n”。
  触发点：_validate_template（__init__.py:81-86）。
  预期标准错误：
    错误：模板包含未知变量：{{age}}（仅支持 {{name}}）
  即标准错误明确指出变量名 age。

6.2 CSV 缺少 segment 列

  将表头改为只有 name,email（删除 segment 整列），数据行相应去掉
  分组字段：
    name,email
    甲,shared@example.invalid
    乙,shared@example.invalid
    丙,bing@example.invalid
  触发点：_parse_contacts 必需列检查（__init__.py:49-56）。
  预期标准错误：
    错误：联系人 CSV 缺少必需列：segment（实际表头：name, email）
  即标准错误明确指出缺失字段 segment，并附实际表头。

6.3 未匹配联系人丙的 name 为空

  CSV 保持三列与三行，仅令第 4 行（archive 的丙）name 留空：
    name,email,segment
    甲,shared@example.invalid,newsletter
    乙,shared@example.invalid,newsletter
    ,bing@example.invalid,archive
  尽管丙本不会被 newsletter 选中，全部行先于筛选接受校验
  （2.3 节），仍整体失败。触发点：__init__.py:67-72。
  预期标准错误：
    错误：联系人 CSV 第 4 行必需字段 name 为空或仅含空白
  即标准错误明确指出行号（第 4 行）与字段名 name。

  对以上三种失败，分别观察两种输出目录状态，预期一致：
  - --out 指向尚不存在的目录：退出 2 后该目录仍不存在；
  - --out 指向预先建好的空目录：退出 2 后该目录仍为空目录。
