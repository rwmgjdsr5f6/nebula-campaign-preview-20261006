一、总体结论
----------------------------------------------------------------
已实现。最小预览流程在 newsletter_preview/__init__.py 的
main()（第 129–162 行）中完整串通，公开入口为
`python -m newsletter_preview`（newsletter_preview/__main__.py
第 7–8 行调用 main()，并以其返回值作为进程退出码），与
README.md「离线预览」一节（第 5–16 行）描述一致：
按 segment 单值精确筛选联系人，为每条匹配记录生成一份
逐人文本预览，并生成一份 report.json；全程离线，不发送邮件。

三、实际处理顺序（main()，newsletter_preview/__init__.py）
----------------------------------------------------------------
以下即源码中的真实先后次序（第 131–158 行），任何一步抛出
InputError 都跳到第 159–161 行：向 stderr 打印「错误：…」并
return 2；全部成功则第 162 行 return 0。

  顺序 | 动作                                   | 源码位置
  -----+----------------------------------------+----------------
   1   | UTF-8 读取联系人 CSV 全文              | 第 133 行 →
       |                                        | _read_text
       |                                        | 第 26–36 行
   2   | UTF-8 读取模板全文                     | 第 134 行 →
       |                                        | _read_text
   3   | 解析并完整校验 CSV（表头与每一行）     | 第 135 行 →
       |                                        | _parse_contacts
       |                                        | 第 39–76 行
   4   | 校验模板占位符（仅允许 {{name}}）      | 第 136 行 →
       |                                        | _validate_template
       |                                        | 第 79–86 行
   5   | 准备输出目录（创建 / 空目录校验）      | 第 137 行 →
       |                                        | _prepare_out_dir
       |                                        | 第 89–102 行
   6   | 按 segment 精确等值筛选，保持 CSV 顺序 | 第 140 行
   7   | 逐人：编号 → 一次性替换 → 写预览文件 → | 第 142–147 行
       |       追加 {email, file} 清单          |
   8   | 组装报告并写入 report.json             | 第 149–158 行

关键次序含义：所有输入读取与校验（步骤 1–4）都在输出目录准备
（步骤 5）之前完成，而任何预览/报告文件的写入最早发生在
步骤 7（_write_file 首次调用，第 146 行）。第九节据此区分
「输入校验失败不产生输出」与「写入失败可能残留部分文件」。

四、关键行为结论（每条标注源码位置）
----------------------------------------------------------------

4.1 UTF-8 输入、原样读入
  - _read_text() 以 open(path, encoding="utf-8", newline="")
    读取（第 29 行）；文件不存在、不可读或非 UTF-8 解码失败
    分别在第 31–36 行转为 InputError（退出码 2）。
  - 模板与 CSV 都要求 UTF-8；读写文本文件统一使用 newline=""
    （读取第 29 行；写入第 108 行），不做换行转换。

4.2 必需字段；未匹配行同样参与校验
  - 必需列固定为 name、email、segment
    （REQUIRED_COLUMNS，第 16 行）。表头缺少任一列即在
    第 50–56 行报错，错误信息给出所缺列名与实际表头。
  - CSV 完全为空（无表头行）在第 43–47 行报错；行字段数与
    表头不一致在第 61–65 行报错；csv 模块解析错误在
    第 74–75 行报错。
  - 校验循环 `for row in reader`（第 59–73 行）遍历全部数据
    行，逐行检查三个必需字段经 .strip() 后不得为空
    （第 67–72 行）。筛选发生在第 140 行、校验全部通过之后，
    因此未匹配 segment 的行同样必须字段齐全；某行不匹配
    并不能豁免其空字段错误。
  - 额外列允许存在：记录只按必需列下标抽取（第 66 行），
    其余列不参与后续处理。

4.3 segment 比较：区分大小写、不修剪空白
  - 筛选就是第 140 行的列表推导：
        matched = [c for c in contacts if c["segment"] == args.segment]
    即 Python == 精确等值：区分大小写，两侧都不做 strip，
    也没有其他归一化。"newsletter"、"Newsletter"、
    " newsletter "互不相等。
  - 唯一与空白有关的处理是第 68 行的空值判定：纯空白单元格
    在校验阶段即被拒绝（无论该行是否会匹配）；而带空白的
    非空值可以通过校验，只是不会与不带空白的筛选值相等。

4.4 预览顺序、编号与共享邮箱
  - matched 直接来自 contacts 的顺序过滤（第 140 行），
    enumerate(..., start=1)（第 142 行）按 CSV 先后顺序
    从 1 连续编号，文件名格式 preview-{序号:04d}.txt
    （第 143 行），即 preview-0001.txt 起，四位补零。
  - 不做去重或合并：同一邮箱出现在多条匹配记录中时，每条
    记录各得一份预览文件、在报告清单中各占一条
    （循环第 142–147 行内逐行 append，无任何按 email 合并的
    逻辑）。

4.5 模板占位符与姓名替换：替换值不再解析
  - 占位符识别用 PLACEHOLDER_RE = r"\{\{([^{}]*)\}\}"
    （第 19 行），只匹配完整双花括号形式；注释（第 18 行）
    明确：不成对的花括号或未闭合写法按普通文字处理。
  - _validate_template() 遍历所有完整占位符（第 81–86 行），
    变量名必须恰为 KNOWN_PLACEHOLDER = "name"（第 17 行），
    否则报「模板包含未知变量：{{变量}}（仅支持 {{name}}）」。
  - 替换只有一次 str.replace（第 145 行）：
        content = template_text.replace("{{name}}", contact["name"])
    替换发生在校验之后，替换进去的姓名值本身不再被解析：
    即使姓名值含有 {{...}} 字样，也作为普通文字保留，不会
    触发二次替换或未知变量错误。
  - 除 {{name}} 被替换为该行 name 列原文外，模板其余正文
    与换行逐字保留：姓名取未修剪的原始单元格值，模板以
    newline="" 读入（第 29 行）、以 newline="" 写入
    （第 108 行），无转义、无 HTML 处理、无额外换行。

4.6 预览文件落盘
  - _write_file() 以 open(path, "x", encoding="utf-8",
    newline="") 独占创建新文件（第 108 行）：目标已存在则
    FileExistsError → InputError（第 110–111 行），其他
    OSError → InputError（第 112–113 行）。正常流程下输出
    目录经第 5 步保证为空且新建，不会覆盖任何已有文件。

4.7 report.json：模板原文、筛选值、人数与清单
  报告在第 149–154 行组装，四个键：
    template      模板文件全文原文（未替换的 template_text，
                  第 150 行），换行也在 JSON 字符串中保留；
    segment       命令行传入的筛选值原文（第 151 行）；
    matched_count 匹配记录数 len(matched)（第 152 行），
                  它同时等于实际写出的预览文件数与 previews
                  清单条数（第 142–147 行每条匹配追加一项）；
    previews      清单，元素为 {"email": 该行邮箱,
                  "file": 预览文件名}（第 147 行），顺序与
                  CSV 中匹配行的顺序、预览编号一一对应。
  序列化与写入在第 155–158 行：json.dumps(..., ensure_ascii=False,
  indent=2) 后追加一个换行；中文不转义，两空格缩进。

4.8 零匹配
  没有任何行满足 segment 时，第 142–147 行循环体一次不执行：
  不生成 preview-*.txt，但报告照常组装（matched_count 为 0、
  previews 为空清单）并在第 155–158 行写出 report.json，
  main() 正常 return 0。即零匹配属于成功运行，退出码 0，
  输出目录中只有 report.json。

4.9 输出目录规则（_prepare_out_dir，第 89–102 行）
  - 路径不存在：os.makedirs(path) 创建（第 100 行，含必要的
    父目录）；创建失败转为 InputError（第 101–102 行）。
  - 路径存在但不是目录：第 92–93 行拒绝，原文件不动。
  - 路径存在且为非空目录：第 94–95 行拒绝（os.listdir 非空
    即报错），目录内原有内容完全不改动（拒绝发生在任何写入
    之前，第 137 行先于第 146 行）。
  - 路径存在、为空但不可写：第 96–97 行拒绝。

4.10 退出码与两类失败的区分
  - 退出码：成功 0（第 162 行）；InputError 一律 2
    （第 159–161 行，stderr 前缀「错误：」）；argparse 参数
    错误亦为 2（第 130 行，见第二节）。
  - 输入校验/读取失败不产生输出：读取失败、CSV 缺列/字段
    数不符/必需字段为空（含未匹配行）、模板未知变量等都在
    步骤 1–4（第 133–136 行）抛出，早于第 137 行的目录准备。
    因此：--out 指向尚不存在的目录时，目录不会被创建；
    --out 指向已存在的空目录时，运行后该目录仍为空。
  - 写入失败不保证回滚：第 137 行可能已新建目录，第 146 行
    起预览文件逐个写出；若此后某次 _write_file() 抛出
    InputError（如写入中途出现 OSError，第 112–113 行；或
    report.json 写入失败，第 155–158 行），异常同样被
    第 159 行捕获、退出 2，但此前已经写出的预览文件与已创建
    的输出目录会保留在磁盘上。源码中没有任何清理或回滚逻辑，
    不应把退出码 2 理解为「本次运行不留下任何文件」——
    「不产生输出」的保证仅适用于写入开始之前的输入校验失败。

5.3 预期结果
  - 进程退出码 0，stderr 无输出（成功路径不打印任何内容）。
  - previews/ 由程序新建，目录中恰好三个文件，无其他内容：
      preview-0001.txt
      preview-0002.txt
      report.json
  - preview-0001.txt 的完整内容（末尾换行保留；共 6 个字符：
    你、好、，、甲、！、LF，UTF-8 编码为 16 字节）：

  - preview-0002.txt 的完整内容（同理）：
      你好，乙！
    丙属于 archive，不匹配 newsletter，不产生任何预览文件。
  - report.json 的完整内容（ensure_ascii=False、两空格缩进、

      "segment": "newsletter",

        {
          "email": "shared@example.invalid",
          "file": "preview-0002.txt"

    template 保留的是替换前的模板原文；matched_count 为 2，

    同一共享邮箱保留为两条相互独立的记录，分别关联
