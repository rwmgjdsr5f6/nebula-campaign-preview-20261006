================================================================

文档日期：2026-10-07
核对基准：Git 提交 530427c（工作区干净）。
源码范围：newsletter_preview/__main__.py、

----------------------------------------------------------------
一、公开入口与实际处理顺序
----------------------------------------------------------------
公开入口（沿用 README 参数）：

  python -m newsletter_preview \
      --contacts contacts.csv \
      --template template.txt \
      --segment newsletter \
      --out previews \
      [--exclude-email EMAIL ...]

必需参数四个：--contacts（联系人 CSV）、--template（模板文本）、
--segment（筛选值）、--out（输出目录）；可选参数 --exclude-email
用 action="append" 收集，可重复提供、每次一个邮箱，缺省为 None
（__init__.py:163-170）。参数定义见 _build_parser
（__init__.py:153-171，required=True 见 159-162）。
入口链：__main__.py:7-8 以 sys.exit(main()) 调用 main()
（__init__.py:174-221）。

main() 中校验、读取、筛选、排除、替换、报告写入的实际顺序
（__init__.py:175-217，try 之内全部包在同一个 try 内）：

  1. 校验并收集 --exclude-email 的值（__init__.py:178，
     _normalize_excludes 定义于 139-150）；
  2. 读取联系人 CSV 文本（__init__.py:179，_read_text
     定义于 29-47，仅此处 strip_bom=True）；
  3. 读取模板文本（__init__.py:180，同一函数，不做 BOM 处理）；
  4. 解析并完整校验全部 CSV 行（__init__.py:181，
     _parse_contacts 定义于 50-87）；
  5. 校验模板占位符（__init__.py:182，_validate_template
     定义于 90-98）；
  6. 准备输出目录：不存在则创建，存在则要求为空且可写
     （__init__.py:183，_prepare_out_dir 定义于 106-125）；
  7. 按 segment 筛选（__init__.py:188），再按排除集合移除
     （__init__.py:189），并收集排除明细（__init__.py:192）；
  8. 按 CSV 顺序逐人替换并写预览文件（__init__.py:196-201，
     替换函数 _render 定义于 101-103，写盘函数 _write_file
     定义于 128-136），同时累积报告清单；
  9. 组装报告并写 report.json（__init__.py:203-217）。

成功返回 0（__init__.py:221）。任何一步抛出本模块的 InputError
（__init__.py:25-26）都由 __init__.py:218-220 捕获，向标准错误
输出一行“错误：……”，返回 2；标准输出不产生内容。
argparse 层面的参数错误（缺参数等）由 argparse 在进入 try 之前
自行处理，同样以退出码 2 终止（__init__.py:175），其标准错误为
argparse 用法信息，不带“错误：”前缀。

关键次序结论：第 1-5 步（排除值校验与两份输入的读取、全部校验）
全部先于第 6 步（创建/检查输出目录）。因此输入校验失败时，输出
目录尚未被创建或写入（详见第四节与第六节）。

----------------------------------------------------------------
二、读取与校验（第 1-5 步）
----------------------------------------------------------------
2.1 UTF-8 输入与联系人 CSV 的起始 BOM

  两份输入均以 open(path, "r", encoding="utf-8", newline="")
  读取（__init__.py:37）。文件不存在、无法以 UTF-8 解码或其他
  读取错误一律转为 InputError（__init__.py:39-44），退出 2，
  且发生在输出目录准备之前。仅联系人 CSV 在读取后移除文件开头
  的一个 U+FEFF（UTF-8 BOM，__init__.py:22、45-46）；字段内部
  的 U+FEFF 属于正文，原样保留。模板文件不做 BOM 处理，其内容
  （含任何位置的 U+FEFF）均按正文保留。写出同样使用 UTF-8 且
  newline=""（__init__.py:131），不做换行转换。

2.2 必需字段与表头

  CSV 首行必须是表头（空文件报错，__init__.py:54-58），且必须
  包含 name、email、segment 三列（REQUIRED_COLUMNS 定义于
  __init__.py:16；逐列检查于 61-66）。列顺序不限，额外列允许
  存在但被忽略——记录只按列名取这三列（__init__.py:77）。
  缺任一必需列即 InputError，错误信息点名缺失列并给出实际表头
  （63-66）。每一数据行的字段数必须与表头一致，否则报错并点名
  行号（__init__.py:72-76）。

2.3 未匹配与将被排除的行同样参与校验

  _parse_contacts 先遍历并校验 CSV 的全部数据行、返回完整记录
  列表（__init__.py:69-84），筛选与排除在其后的第 7 步才发生
  （__init__.py:188-192）。因此某行即使 segment 不等于筛选值、
  或 email 在排除集合中、最终不会生成预览，其 name、email、
  segment 字段为空或仅含空白时仍会导致整体失败（逐字段检查见
  78-83，行号取 reader.line_num，错误信息同时点名字段名）。
  注意 .strip() 仅用于“是否为空”的判定（79 行），存入记录与
  后续比较、替换使用的都是未修剪的原值。
  CSV 词法错误由 csv.Error 捕获并转为 InputError（85-86）。

2.4 模板占位符

  完整双花括号占位符由 PLACEHOLDER_RE = r"\{\{([^{}]*)\}\}"
  识别（__init__.py:19）；只允许 {{name}}、{{email}}、
  {{segment}} 三种（KNOWN_PLACEHOLDERS 定义于 17）。出现任何
  其他完整占位符（如 {{age}}）即 InputError，信息中点名该变量
  （__init__.py:92-98）。未闭合或不成对的花括号不匹配该正则，
  按普通文字保留。

2.5 排除值校验（第 1 步）

  _normalize_excludes（__init__.py:139-150）在读取任何文件之前
  执行：任一 --exclude-email 值为空字符串或仅含空白即
  InputError，错误信息点名 --exclude-email 参数（147-149），
  退出 2。合法值原样收入 frozenset（150 行）：保留原文（区分
  大小写、不去除两端空白），且集合语义使重复提供的同一排除值
  不叠加效果——同一邮箱提供一次与提供多次，排除结果完全相同。

----------------------------------------------------------------
三、筛选、排除与替换（第 7-8 步）：每条记录的去向
----------------------------------------------------------------
3.1 筛选与排除语义

  筛选与排除都是一次 Python 字符串比较（__init__.py:188-192）：
  - 筛选：c["segment"] == args.segment（188 行）；
  - 排除：c["email"] in excluded_emails（189、192 行）。
  因此：
  - 区分大小写："Newsletter" 不等于 "newsletter"，该联系人不
    入选；"Shared@example.invalid" 不等于排除值
    "shared@example.invalid"，该记录不被排除；
  - 不修剪空白：CSV 中的值、命令行筛选值与排除值都按原文比较，
    "newsletter "（带尾空格）不匹配 "newsletter"；
  - 不做包含、前缀或任何归一化匹配。

  每条 CSV 数据记录的去向只有三种，且互斥：
  - segment 不命中：不生成预览、不计入任何计数、不进排除明细，
    但仍参与 2.3 节的完整校验；
  - segment 命中且 email 在排除集合中：计入 segment_count 与
    excluded_count，按 CSV 顺序进入排除明细，不生成预览；
  - segment 命中且 email 不在排除集合中：计入 segment_count 与
    matched_count，生成一份预览并进入报告清单。
  注意排除只作用于 segment 命中的记录：email 命中排除值但
  segment 不命中的记录不出现在排除明细中（excluded 由
  segment_matched 再过滤得到，__init__.py:192）。

3.2 计数、编号、顺序与共享邮箱

  计数均按 CSV 数据记录统计，不按唯一邮箱（__init__.py:193-194、
  211）：多条记录共享同一邮箱时，每条命中记录各计一次
  segment_count，被排除时各计一次 excluded_count。三个人数满足
  恒等式 segment_count == excluded_count + matched_count
  （matched 与 excluded 是对 segment_matched 的互补划分，
  188-192 行）。
  保留记录保持 CSV 中的出现顺序（188-189 行列表推导），自 1 起
  连续编号（enumerate(..., start=1)，__init__.py:196），文件名
  格式 preview-{编号:04d}.txt（197 行），即 preview-0001.txt、
  preview-0002.txt……编号只按保留记录连续分配，不因未匹配行或
  被排除行留空号。
  共享邮箱不做任何合并：每条保留记录各生成一份独立预览、在报告
  清单中各占一项（循环逐条写入与追加见 __init__.py:196-201）。

3.3 替换与正文保留

  正文由 _render 对模板做单次正则扫描生成（__init__.py:101-103、
  199）：每个完整占位符 {{name}}、{{email}}、{{segment}} 替换为
  当前记录对应字段的原始值（{{segment}} 为该记录 segment 列的
  原文，保留大小写与首尾空白）：
  - 替换值（字段内容）不再被解析：即使字段值里含有花括号文字，
    也不会被当作占位符二次处理（单次 sub 完成，不递归）；
  - 模板中除三种已知占位符以外的全部文字原样保留；
  - 读写均以 newline="" 打开（37、131 行），换行与正文逐字节
    保留，模板末尾的换行同样保留。

  由此可直接核对“谁会看到哪份正文”：第 N 个保留联系人的字段被
  写入 preview-000N.txt，邮箱与文件名的对应关系由报告清单给出
  （3.4 与第五节表格）。

3.4 报告内容（第 9 步）

  报告为一个 JSON 对象（__init__.py:203-213），字段依次为：
  - "template"：模板原文（template_text，含原始换行，204 行）；
  - "segment"：命令行给出的筛选值原文（205 行）；
  - "segment_count"：排除前的分组命中记录数（206 行，193 行
    计算）；
  - "excluded_count"：因 --exclude-email 被移除的记录数
    （207 行，194 行计算）；
  - "excluded_contacts"：排除明细清单，每项 {"name": ...,
    "email": ...}，取原始字段值，按 CSV 顺序排列，共享邮箱的
    每条命中各列一项、重复项保留（208-210 行，192 行收集）；
  - "matched_count"：最终预览人数，len(matched)（211 行）；
  - "previews"：预览清单，每项 {"email": ..., "file": ...}，
    按生成顺序排列（201 行追加，212 行入报告）。
  序列化用 json.dumps(..., ensure_ascii=False, indent=2) 并在
  末尾补一个换行（__init__.py:214-217），中文不转义。
  matched_count、previews 清单长度、实际写出的 preview 文件数
  三者一一对应；segment_count 等于 excluded_count 与
  matched_count 之和。
  零命中（segment_count 为 0）或全部排除（matched_count 为 0）
  都退出 0：不生成任何 preview 文件，只生成 report.json，其中
  matched_count 为 0、previews 为空清单 []（循环 196-201 一次
  不执行，报告仍在 214-217 写出）。

----------------------------------------------------------------
四、输出目录与两类失败的区别
----------------------------------------------------------------
4.1 输出目录规则（_prepare_out_dir，__init__.py:106-125）

  - 目录不存在：创建它（os.makedirs，121-125 行）；
  - 路径已存在但不是目录：拒绝，InputError（109-110 行）；
  - 目录已存在且非空：拒绝，InputError（117-118 行），退出 2，
    目录中原有内容不变（程序在此中止，不会写任何文件）；
  - 目录条目无法读取：拒绝，InputError（111-116 行）；
  - 目录已存在、为空但不可写：拒绝，InputError（119-120 行）；
  - 创建目录失败：InputError（122-125 行）。
  写文件一律用 open(path, "x") 独占新建（__init__.py:131），
  文件已存在也转为 InputError（133-134 行），不覆盖任何已有
  文件。

4.2 输入校验失败：不产生任何输出

  排除值为空、读取失败、CSV 缺列/字段为空/字段数不一致/解析
  失败、模板含未知变量，均发生在第 1-5 步，先于输出目录准备
  （__init__.py:178-182 对 183 行）。因此：
  - 若 --out 目录尚不存在，运行后仍不存在（不会被创建）；
  - 若 --out 目录已存在且为空，运行后仍是空目录（不会留下
    文件）。
  非空目录拒绝（4.1）同样不改变其原有内容。

4.3 写入失败：退出 2，但无回滚保证

  第 8-9 步逐个写文件（__init__.py:196-201 写预览，214-217 写
  report.json）。若中途某个 _write_file 因操作系统层错误抛出
  InputError（__init__.py:135-136），控制流同样跳到 218-220，
  退出码仍为 2；但源码中没有任何删除或回滚逻辑——此前已经写出
  的预览文件会保留在输出目录中（例如报告写入失败时，此前写出的
  preview 文件已全部存在）。因此“退出 2 且无输出”的结论只适用
  于第 4.2 节的输入校验阶段；写入阶段失败后，目录可能处于部分
  写入状态，本文不承诺、源码也不提供原子性或回滚。

----------------------------------------------------------------
五、固定样例：甲、乙、丙、丁（预期结果，非实测记录）
----------------------------------------------------------------
以下为完整固定样例。联系人为合成数据，邮箱使用 RFC 2606 保留的
example.invalid 虚构域名；甲、乙同属 newsletter 且共享同一邮箱，
丙属 newsletter，丁属 archive。预期结果逐字依据第一至四节引用
的源码推导，可照此自行执行核对，但它不是某次运行的记录。

5.1 输入文件

contacts.csv（UTF-8，首行表头，恰好四行数据）：

  name,email,segment
  甲,shared@example.invalid,newsletter
  乙,shared@example.invalid,newsletter
  丙,bing@example.invalid,newsletter
  丁,ding@example.invalid,archive

即：甲（第 2 行）与乙（第 3 行）segment 均为 newsletter、邮箱
均为 shared@example.invalid；丙（第 4 行）segment 为
newsletter，邮箱 bing@example.invalid；丁（第 5 行）segment
为 archive，邮箱 ding@example.invalid。

template.txt（UTF-8，内容为下述一行后接恰好一个换行（LF）；
共 39 个字符、59 字节）：

  你好，{{name}}！邮箱{{email}}，分组{{segment}}。
  （文件末尾一个换行）

5.2 两条命令（与 README 相同的参数形式）

  命令一（不排除任何邮箱，输出到空目录 out-all）：

  python -m newsletter_preview \
      --contacts contacts.csv \
      --template template.txt \
      --segment newsletter \
      --out out-all

  命令二（重复两次排除 shared@example.invalid，输出到另一个
  独立空目录 out-excl）：

  python -m newsletter_preview \
      --contacts contacts.csv \
      --template template.txt \
      --segment newsletter \
      --out out-excl \
      --exclude-email shared@example.invalid \
      --exclude-email shared@example.invalid

  两个输出目录互不相同，各自在运行前不存在或为空目录。

5.3 命令一的预期结果（不排除）

  - 退出码 0，标准错误为空（__init__.py:221；成功路径不打印）；
  - out-all/ 目录在不存在时被创建，其中恰好四个文件：
    preview-0001.txt、preview-0002.txt、preview-0003.txt、
    report.json，无其他文件；
  - 三个计数依次为 segment_count=3、excluded_count=0、
    matched_count=3（__init__.py:193-194、211）；
  - 三份预览的完整内容（各保留模板末尾的换行）：
      preview-0001.txt：你好，甲！邮箱shared@example.invalid，分组newsletter。\n
      preview-0002.txt：你好，乙！邮箱shared@example.invalid，分组newsletter。\n
      preview-0003.txt：你好，丙！邮箱bing@example.invalid，分组newsletter。\n
    前两份各 44 个字符、66 字节，第三份 42 个字符、64 字节
    （__init__.py:199 配合 131 行 newline="" 写入）；
  - 不为丁生成任何预览（"archive" != "newsletter"，
    __init__.py:188）。

  每条记录的去向（编号、邮箱与正文的对应关系）：

    CSV 行 | 姓名 | 邮箱                    | segment    | 去向 | 文件              | 正文（含末尾换行）
    ------+----+-------------------------+------------+----+-------------------+------------------------------------------
     2    | 甲 | shared@example.invalid  | newsletter | 保留 | preview-0001.txt | 你好，甲！邮箱shared@example.invalid，分组newsletter。\n
     3    | 乙 | shared@example.invalid  | newsletter | 保留 | preview-0002.txt | 你好，乙！邮箱shared@example.invalid，分组newsletter。\n
     4    | 丙 | bing@example.invalid    | newsletter | 保留 | preview-0003.txt | 你好，丙！邮箱bing@example.invalid，分组newsletter。\n
     5    | 丁 | ding@example.invalid    | archive    | 落选 | （不生成）        | （不生成）

  共享邮箱 shared@example.invalid 收到的是两条互相独立的记录，
  对应两份不同正文，不合并、不去重（__init__.py:196-201）。

  out-all/report.json 的完整预期内容（中文不转义、两空格缩进、
  文件末尾有一个换行；__init__.py:214-217）：

  {
    "template": "你好，{{name}}！邮箱{{email}}，分组{{segment}}。\n",
    "segment": "newsletter",
    "segment_count": 3,
    "excluded_count": 0,
    "excluded_contacts": [],
    "matched_count": 3,

      {
        "email": "shared@example.invalid",

5.4 命令二的预期结果（重复两次排除 shared@example.invalid）

  - 退出码 0，标准错误为空；
  - 排除值重复提供两次不叠加：frozenset 去重后等价于排除一次
    （__init__.py:150），甲、乙各被移除一次而非两次；
  - out-excl/ 目录中恰好两个文件：preview-0001.txt、
    report.json，无其他文件；
  - 三个计数依次为 segment_count=3、excluded_count=2、
    matched_count=1，满足 3 = 2 + 1（3.2 节恒等式）；
  - 排除明细依序为甲、乙（按 CSV 顺序，__init__.py:192、
    208-210）；丁虽邮箱不在排除集合中但 segment 不命中，本来
    就不进任何计数；若排除值命中的是丁的邮箱，丁也不会出现在
    排除明细中（排除只作用于 segment 命中记录）；
  - 唯一保留记录是丙，按保留记录连续编号，故唯一预览仍名为
    preview-0001.txt（不因甲、乙被排除而留空号或从 3 起编），
    其完整内容为 42 个字符、64 字节：
      你好，丙！邮箱bing@example.invalid，分组newsletter。\n

  每条记录的去向：

    CSV 行 | 姓名 | 邮箱                    | segment    | 去向   | 文件              | 正文（含末尾换行）
    ------+----+-------------------------+------------+------+-------------------+------------------------------------------
     2    | 甲 | shared@example.invalid  | newsletter | 被排除 | （不生成）        | （不生成；进排除明细第 1 项）
     3    | 乙 | shared@example.invalid  | newsletter | 被排除 | （不生成）        | （不生成；进排除明细第 2 项）
     4    | 丙 | bing@example.invalid    | newsletter | 保留   | preview-0001.txt | 你好，丙！邮箱bing@example.invalid，分组newsletter。\n
     5    | 丁 | ding@example.invalid    | archive    | 落选   | （不生成）        | （不生成；不进排除明细）

  out-excl/report.json 的完整预期内容（格式同 5.3）：

  {
    "template": "你好，{{name}}！邮箱{{email}}，分组{{segment}}。\n",
    "segment": "newsletter",
    "segment_count": 3,
    "excluded_count": 2,
    "excluded_contacts": [
      {
        "name": "甲",
        "email": "shared@example.invalid"
      },
      {
        "name": "乙",
        "email": "shared@example.invalid"
      }
    ],
    "matched_count": 1,
    "previews": [
      {
        "email": "bing@example.invalid",
        "file": "preview-0001.txt"
      }
    ]
  }

  "template" 保留模板原文（含三种占位符与末尾换行），"segment"
  保留筛选值原文；matched_count 与清单一一项、一份预览文件严格
  对应；excluded_contacts 只存原始 name 与 email，按 CSV 顺序
  （__init__.py:203-213）。

六、四类输入失败样例（预期结果，非实测记录）
----------------------------------------------------------------
下列四种输入均在第 1-5 步校验失败（先于输出目录准备），预期退
出码 2；标准错误为一行“错误：……”且不含未捕获异常的
Traceback（__init__.py:218-220）；尚不存在的输出目录不会被创
建，已存在的空目录保持为空（4.2 节）。除注明处外，其余输入沿
用第五节。

6.1 模板含未知变量 {{age}}

  将 template.txt 改为在末尾换行前再加一行 {{age}}，例如内容为
  “你好，{{name}}！邮箱{{email}}，分组{{segment}}。\n{{age}}\n”。
  触发点：_validate_template（__init__.py:92-98）。
  预期标准错误：
    错误：模板包含未知变量：{{age}}（仅支持 {{name}}、{{email}}、{{segment}}）
  即标准错误明确指出变量名 age。

6.2 CSV 缺少 segment 列

  将表头改为只有 name,email（删除 segment 整列），数据行相应
  去掉分组字段：
    name,email
    甲,shared@example.invalid
    乙,shared@example.invalid
    丙,bing@example.invalid
    丁,ding@example.invalid
  触发点：_parse_contacts 必需列检查（__init__.py:61-66）。
  预期标准错误：
    错误：联系人 CSV 缺少必需列：segment（实际表头：name, email）
  即标准错误明确指出缺失列 segment，并附实际表头。

6.3 未匹配联系人丁的 name 为空

  CSV 保持三列与四行，仅令第 5 行（archive 的丁）name 留空：
    name,email,segment
    甲,shared@example.invalid,newsletter
    乙,shared@example.invalid,newsletter
    丙,bing@example.invalid,newsletter
    ,ding@example.invalid,archive
  尽管丁本不会被 newsletter 选中，全部行先于筛选与排除接受校
  验（2.3 节），仍整体失败。触发点：__init__.py:78-83。
  预期标准错误：
    错误：联系人 CSV 第 5 行必需字段 name 为空或仅含空白
  即标准错误明确指出行号（第 5 行）与字段名 name。将被排除的
  记录同理：若第 2 行（甲）name 留空，即使命令二会把甲排除，
  仍在第 4 步整体失败，报第 2 行 name 为空。

6.4 排除值为空白

  在命令二基础上把任一 --exclude-email 的值改为空字符串 ""
  （或仅含空白，如 "  "）。
  触发点：_normalize_excludes（__init__.py:147-149），在读取
  任何输入文件之前执行。
  预期标准错误：
    错误：--exclude-email 的值不能为空字符串或仅含空白
  即标准错误明确指出 --exclude-email 参数。

  对以上四种失败，分别观察两种输出目录状态，预期一致：
  - --out 指向尚不存在的目录：退出 2 后该目录仍不存在；
  - --out 指向预先建好的空目录：退出 2 后该目录仍为空目录。
